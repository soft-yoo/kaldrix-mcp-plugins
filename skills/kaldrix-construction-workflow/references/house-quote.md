## Client house quote

The most common request: "prepare a quote for a house for my client". Start from `create_quick_house`, not from drawing walls.

1. Client: `list_customers`; when new, `lookup_company_by_nip` (company) or ask for the details, then `create_customer`.
2. Price list ready: `get_company_workflow` tells whether the company has a price list with services. Without one, `list_demo_price_lists` + `copy_price_list` with `source=DEMO`, or `install_construction_starter_pack` on the default list (`list_price_lists`).
3. House model and estimate in one call: `create_quick_house` (shape, dimensions, storeys, attic, technology, foundation, roof; `customerId`, address). It creates the project, the primary estimate on the default price list and prices it from the model (shell, finishing, installations).
4. Plan changes the client asked for: `get_floor_detail`, `create_partition` and `label_room` for rooms, `add_opening_by_intent` for windows and doors, `create_roof` / `update_roof` (pitch, type, overhang — the framing follows) / `remove_roof`, `set_floor_roof_space` for the attic, `set_building_outline` (outline or width + depth) for the footprint. `render_floor_svg` shows the plan; `validate_project_geometry` checks it.
5. Installations for the estimate (optional; the planning and circuit tools need INSTALLATION_DESIGN): `plan_floor_installations` for one reviewed floor version shows SOURCE → POINTS → CONNECT for all six trades or the selected systems. Choose the trades needed for this building. Follow the returned actions to place sources, add room presets with `add_installation_point_presets_for_floor`, then preview `suggest_installation_circuits` before `apply_installation_circuit_suggestions`. For a multi-storey building, also review the source-floor connections to each installation riser: cold water from the meter, hot water from a domestic hot-water source, heating from the heat source and gas from the meter are included as RISER_FEED suggestions. The vertical run is counted separately. Read the plan again after saving, then inspect `list_installation_circuits`, `list_installation_risers` and `validate_floor_geometry`: satisfied authoring steps do not replace route validation.
   To improve saved automatic routes, use `preview_circuit_optimization` with a chosen goal and inspect its full before/after physical segments. Apply only a valid reviewed proposal with exact inputs after confirmation; preserve manual networks and follow unavailable-result guidance. This is bounded planning, not proof of a global optimum or full standards compliance. Validate both each floor and the whole project before reporting installation readiness.
6. Estimate after model changes: a draft estimate corrects its model quantities by itself shortly after each model change (read them with `get_estimate_model_changes`; do not apply them again). `review_estimate_against_model` shows what is left and only proposes; `apply_estimate_model_changes` accepts new elements and remaining changes explicitly; removed elements need the user's choice (`detach_estimate_items_from_model` or `remove_estimate_items_with_missing_source`). New automatic stage positions also propose matching new walls, slabs and rooms across the estimate's allowed building/project scope, within their original stage and work section. Older and manually scoped positions keep their existing floor rules and source types. `price_estimate_from_model` (SHELL, FINISHING, INSTALLATIONS) is a separate option: it adds only unpriced sources in complementary positions, preserving earlier rows, quantities and prices. After `create_partition`, inspect the review and coverage; explicitly repeat FINISHING if a missing room is not proposed, and inspect manual quantities. To deliberately change selected scopes, read `list_estimate_sheet_rows`, then use `preview_estimate_position_scope` + `assign_estimate_position_scope`; a manual scope change ends that position's automatic stage coverage. Single positions: `quick_add_estimate_position`, `update_estimate_sheet`, `remove_estimate_position`.
7. Check: `get_estimate_checks` (offerReadiness and fix tools).
8. Offer: `update_project_estimate` with `offer` (number, validity, payment terms, recipient, exclusions, signatures) and `presentationMode` SIMPLE for a client offer; `generate_estimate_pdf` stores the PDF in project documents and returns a download link. Every `update_project_estimate` call and `generate_estimate_pdf` need `confirm=true` after the user approves the change.
9. Sending (only when the user says so): `get_estimate_offer_workflow` (canSend), then `send_estimate_offer` with `confirm=true` after showing the user the recipient and message. The client's answer arrives in `get_estimate_offer_workflow.latestOffer`; `revoke_estimate_offer` withdraws the link.
10. Approving the estimate yourself (`update_project_estimate` status APPROVED) makes it immutable and requires `confirm=true` after an explicit user decision.

## Client house quote

Most common request: "prepare a quote for a house for my client". Start from `create_quick_house`, not from drawing walls.

1. Client: `list_customers`; if new, `lookup_company_by_nip` (company) or ask for details, then `create_customer`.
2. Price list: `get_company_workflow` tells whether one with services exists. If not: `list_demo_price_lists` + `copy_price_list` with `source=DEMO`, or `install_construction_starter_pack` on the default list (`list_price_lists`).
3. `create_quick_house` (shape, dimensions, storeys, attic, technology, foundation, roof; `customerId`, address) creates the project and the primary estimate on the default price list, priced from the model (shell, finishing, installations).
4. Requested plan changes: `get_floor_detail`, `create_partition` and `label_room` (rooms); `add_opening_by_intent` (windows, doors); `create_roof` / `update_roof` (pitch, type, overhang — framing follows) / `remove_roof`; `set_floor_roof_space` (attic); `set_building_outline` (outline or width + depth). `render_floor_svg` shows the plan; `validate_project_geometry` checks it.
5. Installations (optional; planning and circuit tools need INSTALLATION_DESIGN): `plan_floor_installations` for one reviewed floor version shows SOURCE → POINTS → CONNECT for all six trades or selected systems; choose the trades this building needs. Follow returned actions: place sources, room presets via `add_installation_point_presets_for_floor`, preview `suggest_installation_circuits` before `apply_installation_circuit_suggestions`. Multi-storey: also review source-floor connections to each riser — cold water from the meter, hot water from a domestic hot-water source, heating from the heat source, gas from the meter come as RISER_FEED suggestions; the vertical run is counted separately. Re-read the plan after saving, then inspect `list_installation_circuits`, `list_installation_risers`, `validate_floor_geometry`: satisfied authoring steps do not replace route validation.
   Better saved automatic routes: `preview_circuit_optimization` with a chosen goal; inspect full before/after physical segments. Apply only a valid reviewed proposal with exact inputs after confirmation; keep manual networks; follow unavailable-result guidance. Bounded planning — no proof of a global optimum or full standards compliance. Validate each floor and the whole project before reporting installation readiness.
6. Estimate after model changes: a draft estimate corrects its model quantities itself shortly after each change (read via `get_estimate_model_changes`; never apply them again). `review_estimate_against_model` shows what is left and only proposes; `apply_estimate_model_changes` explicitly accepts new elements and remaining changes, with required `expectedModelVersion` copied from the review's `modelVersion`. Removed elements need the user's choice: `detach_estimate_items_from_model` or `remove_estimate_items_with_missing_source`. New automatic stage positions also propose matching new walls, slabs and rooms across the estimate's allowed building/project scope, within their original stage and work section; older and manually scoped positions keep their floor rules and source types. `price_estimate_from_model` (SHELL, FINISHING, INSTALLATIONS) separately adds only unpriced sources in complementary positions, keeping earlier rows, quantities and prices. After `create_partition` inspect review and coverage; repeat FINISHING explicitly if a missing room is not proposed; inspect manual quantities. Deliberate scope change: `list_estimate_sheet_rows`, then `preview_estimate_position_scope` + `assign_estimate_position_scope` (ends that position's automatic stage coverage). Single positions: `quick_add_estimate_position`, `update_estimate_sheet`, `remove_estimate_position`.
7. Check: `get_estimate_checks` (offerReadiness, fix tools).
8. Offer: `update_project_estimate` with `offer` (number, validity, payment terms, recipient, exclusions, signatures) and `presentationMode` SIMPLE for a client offer; `generate_estimate_pdf` stores the PDF in project documents and returns a download link. Every `update_project_estimate` call and `generate_estimate_pdf` need `confirm=true` after user approval.
9. Sending (only when the user says so): `get_estimate_offer_workflow` (canSend), then `send_estimate_offer` with `confirm=true` after showing recipient and message. The answer arrives in `get_estimate_offer_workflow.latestOffer`; `revoke_estimate_offer` withdraws the link.
10. Approving yourself (`update_project_estimate` status APPROVED) makes the estimate immutable; needs `confirm=true` after an explicit user decision.

Before PDF, sending or approval, read `review_estimate_against_model` again. Resolve `blockingPublicationItemIds` first: removed and zero-quantity sources block the action even with consent. Explain `hasPublicationWarnings` and unacknowledged automatic quantity changes. Only after explicit acceptance send `confirmModelWarnings=true` with that review's `modelVersion` as `expectedModelVersion`, besides `confirm=true`; the backend checks the current model itself. On `ESTIMATE_MODEL_REVIEW_STALE`, review the new state and get a new decision; never silently replace the version.

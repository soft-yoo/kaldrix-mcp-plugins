## Startup and Discovery

1. Read the server instructions returned by MCP `initialize`.
2. Call `describe_kaldrix_mcp` when this guide has not already been loaded. Omit `resourceUri` for this overview; send a URI from its input enum for one focused guide or catalogue. The tool returns the selected content directly; the client does not need `resources/read`. Examples of compact server contracts: `kaldrix://projects/installation-point-kinds` and `kaldrix://documents/agent-documentation-policy`. Prefer the installed BIM or service-estimation skill for a procedure; full project/estimation guide URIs remain fallback reads on demand.
3. For compact discovery, call `describe_kaldrix_mcp` with `resourceUri=kaldrix://mcp/tool-groups` and select the relevant domain. Read `kaldrix://mcp/service-catalog` when you need tool, scope and focused-resource details. Do not load every tool definition for a single task. Treat the runtime tool list as authoritative; never invent a tool name. Use exact input field names from its schemas, including nested parameters and array items; unknown fields are rejected instead of silently ignored.
4. Use the single complete `workspace` catalog on `/mcp` (also available at `/mcp/profiles/workspace`). All domains share this connection; no profile selection or switching is needed.
5. `tools/list` shows only tools this connection may use: the person's current scopes narrowed by consent (see "Permissions: you act as the person"), enabled modules and company type. PERSONAL and ORGANIZATION client accounts use the same plan rules: invoices require INVOICES and their declared scopes, not an account-kind conversion. A PERSONAL account starts with Offers, Customers, Invoices, Tasks, Time tracking and History switched off, an ORGANIZATION account with History off, until the owner enables them. Read the returned entitlement and diagnostic reason instead of inferring access from a plan or template name.
6. Inspect existing objects before a mutation and reuse identifiers returned by Kaldrix.

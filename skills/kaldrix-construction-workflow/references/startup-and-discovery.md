## Startup and Discovery

1. Read the server instructions returned by MCP `initialize`.
2. Call `describe_kaldrix_mcp` unless this guide is loaded: omit `resourceUri` for this overview, or send a URI from its input enum for one focused guide or catalogue (e.g. `kaldrix://projects/installation-point-kinds`, `kaldrix://documents/agent-documentation-policy`). Content is returned directly; `resources/read` is not needed. Prefer the installed BIM or service-estimation skill for a procedure; full project/estimation guide URIs are fallback reads on demand.
3. Compact discovery: `describe_kaldrix_mcp` with `resourceUri=kaldrix://mcp/tool-groups`, then the relevant domain; `kaldrix://mcp/service-catalog` for tool, scope and focused-resource details. Do not load every tool definition for one task. The runtime tool list is authoritative; never invent a tool name. Use exact input field names from its schemas, including nested parameters and array items; unknown fields are rejected, not ignored.
4. One complete `workspace` catalog on `/mcp` (also `/mcp/profiles/workspace`) serves all domains; no profile selection or switching is needed.
5. `tools/list` shows only tools this connection may use: the person's current scopes narrowed by consent (see "Permissions: you act as the person"), enabled modules and company type (account-kind module defaults: see "Private investor accounts"; invoices need INVOICES and their declared scopes, not an account-kind conversion). Read the returned entitlement and diagnostic reason; never infer access from a plan or template name.
6. Inspect existing objects before a mutation and reuse identifiers returned by Kaldrix.

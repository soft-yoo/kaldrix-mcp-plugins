## Required order

1. Resolve the project with `get_projects` or `get_project_detail`. New project: `create_project(idempotencyKey, name, description, type)` creates one named building; read `projectId`, `created.buildingId` and `modelVersion`. Optional `outline: {width: 10, depth: 8}` saves its initial rectangular footprint in the same call, without creating floors.
2. Keep `created.buildingId` for the house; do not create another building for it by default. `save_project_building` is optional: the existing UUID renames or describes it, a new UUID only adds another building such as a garage.
3. Without a footprint, call `set_building_outline` before adding floors: ordered outer-face polygon vertices (do not repeat the first) and a positive `wallThickness`. Reuse dimensions already sent to `create_project`. A 10×8 m footprint is `[{x:0,y:0},{x:10,y:0},{x:10,y:8},{x:0,y:8}]`.
4. After user review, call `create_building_floor` with `buildingId`, floor name, level, type, elevation, current version, a stable `idempotencyKey` and `confirm=true`. Regular storey: exactly one of `height` (floor-to-floor, including the ceiling slab) or `clearHeight` (to the ceiling); the backend returns both. Roof-dependent attic: gross `height`. Omit `ceilingThickness` unless the user deliberately changes an unassigned slab's thickness; never write a returned `DEFAULT_PROFILE` merely to persist the assumption. Full rules: [geometry guide](geometry-guide.md#floor-and-room-heights). Needs `projects.write` and `projects.delete`: an upper storey can move and rebuild an existing roof. The backend creates envelope walls and the initial interior. Further floors with the same building UUID inherit the footprint; `set_floor_outline` only for a differing storey (a null outline restores inheritance).
5. Read `get_floor_detail` for envelope wall paths, then `create_partition` with axis points, thickness and an internal type (`PARTITION`, `INTERNAL_LOAD_BEARING` or `VIRTUAL`). A partition reaching surrounding walls subdivides the interior into rooms automatically. Draw each shared partition once; never create adjacent room rectangles. An unfinished partition reduces usable area but need not create a room. The backend owns validation and topology.
6. Re-read `get_floor_detail` after each physical edit. `label_room` with the current derived room UUID, name and function; omit `height` and `resetHeight` for a label-only change (they set a lower own ceiling or restore AUTO). The room outline is backend output; never build separate room rectangles or duplicate shared walls.
7. Add wall-hosted openings with `add_opening_by_intent`; prefer an explicit wall UUID for windows and external doors. Room references help placement; the opening belongs to its wall.
8. Call `create_roof` on the highest building floor: `roof: {}` gives the app's default roof; `roofType` and, for a pitched roof, at most one of `pitchDegrees` (simplest), `ridgeHeight` or `ridgeElevation` override it. Its footprint is the effective floor outline; room divisions do not define it. Roof heights are floor-local. Keep the returned roof assembly UUID for removal/replacement.
9. Configure the existing shared floor and ceiling surfaces. Add room- or floor-scoped structures and installations with their typed tools. `buildUps` are reusable layered construction definitions referenced by walls and slabs, not buildings or floors.
10. Call `validate_project_geometry` and inspect quantities and warnings before reporting completion; `render_floor_svg` when useful.

## More than one building

For a garage or another house, repeat building metadata, footprint and floor creation in the same project. Keep the intended `buildingId` explicit. Each roof uses the highest floor of its own building. Building-local risers and structural supports do not link independent buildings. Site geometry stays outside their floor collections.

Shared terrain: call `create_site_floor` once per project, without a building UUID or outline, with `name`, explicit `level` (usually 0; a logical index, not an elevation), `height` in metres (e.g. 2), current `expectedModelVersion` and `idempotencyKey`. Optional `elevation` is absolute terrain elevation in metres; omitted = ground-floor elevation, or project datum without a ground floor. A second SITE is rejected. An identical retry returns the saved floor UUID and version; never change the input or reviewed version under the same key. It leaves building storeys, roofs and project parts unchanged and creates no plot outline, paving, fence or inter-building connection. Read `get_floor_detail` / `get_project_detail` afterwards; edit with `update_floor`. `set_floor_outline` applies to building storeys and cannot define a site boundary.

`get_project_purchase_report` and `get_timber_schedule`: send the building UUID from `get_project_detail` for one building, omit `buildingId` for the whole project including site geometry. Both echo `buildingId` (`null` = whole project); a UUID from another project is rejected with `BUILDING_NOT_FOUND`. Floor names and levels are not identifiers: two buildings may both have a ground floor `Parter` at level 0.

Compare raw quantities in the same unit. Each timber cut list is optimized for its own scope, so whole-project purchased bars or rounded row groups need not equal the sum of building reports. The model purchase report reads the current model, not frozen estimate positions; for a saved estimate use `get_estimate_purchase_resources`.

### Removing one building

Read `get_project_detail`, identify the exact building UUID and review its floors, installations, saved views and estimate scope. Only after explicit confirmation call `remove_building` with `confirm=true`, `projects.delete`, the reviewed positive `expectedModelVersion` and a stable `idempotencyKey`. It permanently removes the building, its owned model elements and building/floor views. Its roof is not transferred; other buildings, project terrain and project views remain. Retained building estimates (inactive ones too) and active underfloor or framing estimate references block removal. Estimates, frozen rows, PDFs and project documents are preserved. During removal, estimate writes can be temporarily refused.

After a timeout or unknown outcome, read the project and retry the exact same intent and key; a changed building or reviewed version needs a newly reviewed intent. Never clear estimate scope or recreate a deleted building UUID to bypass a refusal. After success, read `get_project_detail` and verify the removed scope and the preserved building/site.

# Tool order and input sources: building model

Tool descriptions say only what each tool does. This page says where inputs come from and which
tool comes next. Live schemas, `nextTools` and `fixTools` in results stay authoritative.

## Project, buildings and floors

- `create_project` without an initial outline: set the footprint with `set_building_outline`, add storeys with
  `create_building_floor`, rename or add buildings with `save_project_building`, change project parts later with
  `set_project_parts`. `PROJECT_CREATE_FORBIDDEN` is final; do not retry.
- `duplicate_project`: check `get_projects` first so the copy gets a unique name.
- `create_building_floor`: set the building outline first. Use `set_floor_outline` only when a storey needs another
  footprint. In a project with several buildings, send the building id explicitly. The auto-created attic roof is
  changed with `update_roof`; an attic roof space is set with `set_floor_roof_space`.
- After `set_building_outline` or `move_building`, read `get_project_detail`.
- `buildingId` comes from `get_project_detail`. Project parts: `get_project_part_catalog` together with
  `get_project_detail` `activeParts` and `set_project_parts`.

## Walls, rooms, slabs and openings

- Envelope walls come only from `set_building_outline` / `set_floor_outline`; their axes and types are edited there.
- `create_partition`: read `get_floor_detail` first (exact wall axes, `envelopeEdgeIndex`). After drawing, read
  `get_floor_detail` again for current room ids and name rooms with `label_room`. Room division changes only with
  `create_partition`.
- Wall ids for `add_beam_between_walls` and other wall references: `get_floor_detail` or `inspect_floor_bim_model`.
- Coordinated edits of several elements: `apply_geometry_batch` (example: `kaldrix://projects/geometry-batch-example`).
  Batch sections mirror single tools: `labelRooms` = `label_room`, `updateWalls` = `update_wall`, `updateSlabs` =
  part of `update_slab`, `createPartitions` = `create_partition`, `createSlabs` = `create_slab`. Removal kinds:
  WALL = `remove_wall`, SLAB = `remove_slab`, INSTALLATION_POINT = `remove_installation_points`,
  STRUCTURAL_MEMBER = `remove_structural_members`, FRAMING_SYSTEM = `remove_framing_system`,
  INSTALLATION_CIRCUIT = `remove_installation_circuits`.
- Slabs: roofs are created with `create_roof`; roof windows, chimneys and stairwells with `add_slab_opening`.
  Slab opening ids for `update_slab_opening` / `remove_slab_openings`: `list_elements` with kind SLAB_OPENING.
  Managed FLOOR/CEILING surfaces are excluded with `set_floor_surface_usage`; a roof slab is removed with its whole
  roof by `remove_roof`.
- Openings: styles and ranges per type come from `get_opening_catalog`; the style is used by `add_opening_by_intent`
  and `update_opening`. Single lintels: `set_opening_lintel`.
- `copy_to_floor`: source ids from `list_installation_points` (points), `list_structures` (members) and
  `get_floor_detail` (walls).
- Measurements: ids come from `get_floor_detail` measurements or `list_elements` (kind MEASUREMENT); paths follow
  `create_measurement`. `get_element` adds references to the `list_elements` fields.

## Validation

- Run `validate_floor_geometry` after geometry changes and finish with `validate_project_geometry`.
- Call the `execute_*_action` tool named in the action's `nextTools` with the action id and `modelVersion` returned by
  `validate_floor_geometry`; the tool name fixes the action kind.

## Structures and framing

- New framing system: `preview_framing_system`, then `create_framing_system` with the same intent and the returned
  `modelVersion`. Saved system: `preview_framing_system` with `sourceSystemId`, then `update_framing_system`.
  Prefer `update_framing_system` over `explode_framing_system`; explode only when the user wants to edit single
  members (then `transform_structural_members` / `update_structural_member`). Changes to spacing, sections, height or
  openings go through `update_framing_system`.
- Do not delete and recreate an estimated plasterboard ceiling to bypass the estimate conversion check. Show
  `suggestion.reason` and warnings to the user.
- Ids: `systemId` and `memberIds` from `list_structures` (or `create_framing_system`); `spaceId` from
  `get_floor_detail`; `roofAssemblyId` from `create_roof` or `list_structures`. Kind defaults:
  `kaldrix://projects/framing-system-kinds`; roof recipes: `kaldrix://projects/roof-construction-recipes`;
  member roles: `kaldrix://projects/structural-member-roles`.
- Single members: `add_structural_members`. A beam on two walls: `add_beam_between_walls`; a post under a beam:
  `add_post_under_member` with the beam `memberId` (returned by `add_beam_between_walls`, or the `beamId` returned by
  `support_purlin_with_beam`). Whole ceilings, joists, roof framing or a timber post frame:
  `create_framing_system`. Members generated by a system change only with `update_framing_system`; do not add every
  generated rafter separately. A post-and-girt frame (cabin, gazebo, carport) is kind TIMBER_POST_FRAME.
- Roof support plan: read `get_roof_support_plan` (stable purlin, post and wall-plate ids, `modelVersion`) before
  `update_roof_support_plan` or `support_purlin_with_beam`. `PURLIN_BEAM_NO_WALL`: add a post there or draw the beam
  with `add_beam_between_walls`. A roof without wall plates: switch `params.wallPlates` off with
  `update_framing_system`.
- Framing members: ids and `modelVersion` for `update_framing_member` come from `get_framing_members` (never preview
  ids or list indices); read `get_framing_members` again afterwards. All physical timber including battens:
  `get_timber_schedule`; an unsaved system: `preview_framing_system`. Removed sources show as SOURCE_REMOVED in
  `review_estimate_against_model`.
- Timber-frame house: `set_technology_build_ups` (or `create_build_up_from_template` + `assign_build_up`), then
  `get_wall_frame` / `get_slab_frame`. Templates: `list_build_ups` with `includeTemplates=true` or
  `kaldrix://projects/build-up-templates`. Doors and windows are inserted with `add_opening_by_intent` and the wall
  frame follows. Joist section, spacing or direction: `create_framing_system` for the floor or a room.
- Construction systems: `preview_construction_system` shows stairs and chimney results to the user; then
  `create_construction_system` with its `modelVersion`. Managed kinds (footings, ring beams, lintels) are tuned or
  disabled with `update_construction_system`; `systemId` from `list_construction_systems`.
- Foundations: wall ids and footing bands from `get_foundation` (or the `add_foundation_wall` result); lowest-storey
  wall ids from `get_floor_detail`. `FOUNDATION_OUTSIDE_WALLS` is reported by floor validation. Ground floor build-up
  templates: `list_build_ups`.

## Installations

- Typical point sets: `add_installation_point_preset` (one room) or `add_installation_point_presets_for_floor`
  (every room); adjust afterwards with `update_installation_point` / `remove_installation_points`. Default mount and
  height per kind: `kaldrix://projects/installation-point-kinds`. Trade guide intents: PLACE_POINT =
  `add_installation_points`, PROPOSE_CIRCUITS = `suggest_installation_circuits`.
- Add circuit source points (DISTRIBUTION_BOARD, WATER_METER, WATER_MANIFOLD, DRAIN_STACK, HEAT_SOURCE,
  UFH_MANIFOLD, GAS_METER…) before `suggest_installation_circuits`. When the result has `missingSources`, add a point
  of `missingSources.suggestedPointKind` and suggest again; with `missingSources.medium`, add that line with
  `update_installation_riser` or add a compatible source. Save with `apply_installation_circuit_suggestions` using
  the returned `modelVersion` and the same system filter and language.
- Manual circuits: read `get_installation_circuit_selection` and use its `modelVersion` in
  `create_installation_circuit` / `update_installation_circuit`; point ids from `list_installation_points`; `spec`
  from `get_installation_conduit_catalog` `allowedSpecs`. For a whole floor prefer the suggest + apply pair. Before
  adding points to an existing circuit, read the selection with `editingCircuitId`. Shared junctions and 3D edges:
  `update_installation_circuit` `nodeEdit`, previewed with `preview_installation_circuit_node` at the same
  `modelVersion`. One branch: `routeOverrides`. `explode_installation_circuit` turns a circuit into plain lines and
  loses parametric behaviour. Summaries and circuit ids: `list_installation_circuits`; geometry:
  `get_installation_circuit_layout`. Examples: `kaldrix://projects/installation-authoring` and
  `kaldrix://projects/structures-and-installations`.
- Trade guides: `expectedModelVersion` for `get_installation_trade_guide` and `plan_floor_installations` comes from
  `get_project_detail`.
- Risers: multi-floor points come from `create_installation_riser`; route each floor to its riser points; riser
  connection points are changed with `update_installation_riser`.
- Ventilation: `suggest_ventilation`, then `apply_ventilation_suggestions` with its `modelVersion` (diffusers), add
  MVHR_UNIT / AIR_DISTRIBUTION_BOX / AIR_INTAKE / AIR_EXHAUST if missing, then the circuit suggest + apply pair with
  `system=VENTILATION`. Duct lengths and warnings: `get_ventilation_route_report` with `list_installation_circuits`
  and `get_installation_circuit_layout`. The whole-project ventilation balance is in `suggest_ventilation`, not in
  the room report.
- Underfloor heating: `preview_underfloor_heating`, then `create_underfloor_heating` with the identical request
  (source UFH_MANIFOLD; never paired heating circuits). Rooms with loops: `preview_underfloor_heating_update`, then
  `update_underfloor_heating`, or `reduce_underfloor_heating` (confirm=true) when the plan has `removedCircuitIds`.
  `pipeProductId` from `get_underfloor_pipe_products`.

## Scene and underlays

- Read `get_project_scene` before any scene write and send its `sceneVersion` as `expectedSceneVersion`
  (`place_graphic_model`, `update_placed_model`, `remove_placed_model`, surface textures, wall texture regions).
  Without the GRAPHICS module read underlays with `get_project_underlays`. Asset ids: `list_graphic_assets`
  (MODEL_3D / TEXTURE).
- Underlays: read `get_project_underlays` (or the scene) first; viewpoints: `get_project_scene_viewpoints`. Read
  again after `SCENE_VERSION_CONFLICT`.

## Roofs, quick house and site

- `create_quick_house` does not divide rooms: continue with `create_partition` and `label_room`, openings with
  `add_opening_by_intent` (styles, sizes and ranges from `get_opening_catalog`), then `review_estimate_against_model`.
- `create_roof`: set the building or floor outline first; editable starting parameters are in
  `kaldrix://projects/roof-construction-recipes`. Timber framing follows: `preview_framing_system` with kind
  ROOF_RAFTERS and the returned `roofAssemblyId`, then `create_framing_system`. Keep framing parametric so the user can
  adjust it in the app.
- Change a roof with `update_roof`, not `remove_roof` + `create_roof` (that deletes its framing). A covering below its
  minimum pitch is reported by `validate_project_geometry` (BIM_ROOF_PITCH_BELOW_COVERING_MINIMUM). `roofAssemblyId`
  comes from `create_roof`, `update_roof` or `list_structures` (`roofAssemblies[].id`).
- Site location: use a point chosen by the user or returned by `find_land_parcel` / `get_land_parcel_at`; never infer
  coordinates from an incomplete address. After `set_project_location` read `get_project_detail`, then
  `get_land_parcel_at` for the saved point. Parcel boundaries are in degrees; never send them to outline tools (metres).
  For a building site returned by `list_map_features`, `targetId` identifies its project; continue with `get_project_detail`.
- Renovation survey: room ids come from `list_survey_rooms`.

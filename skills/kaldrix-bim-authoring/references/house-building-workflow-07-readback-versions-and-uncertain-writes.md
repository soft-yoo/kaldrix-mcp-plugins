## Readback, versions and uncertain writes

- Read `get_floor_detail` for the actual envelope axes before drawing partitions. The outer-face footprint is not a wall axis; never guess half-thickness offsets. Re-read after each physical change and after automatic building placement.
- Every physical model write (including roof creation/removal, opening intents, installation point edits/presets and framing writes) requires `expectedModelVersion` from the state you reviewed. `preview_framing_system` returns the version to use for its save. A preview is advisory, not a reserved transaction: after any intervening edit, read the scope and review the changed input. Never substitute a fresh version into a stale proposal; a confirmed version conflict means reread and replan. Always inspect the saved result and validation warnings.
- Every individual element create/add tool also requires a stable `idempotencyKey`. After an uncertain response, reuse the key with the exact same input (including the reviewed version): the backend returns the original committed result without another element. Changed input needs a new key and a freshly reviewed version. Do not identify a retry by name.
- A replayed result keeps its original modelVersion. Read get_project_detail before planning another edit; the live project may have changed since that command committed.
